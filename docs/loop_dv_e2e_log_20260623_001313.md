## Goal & method

Policy: regular arrays MUST become `array_dv` for C lowering (`array of` →
`array_dv of`). Workflow per file: **copy** `loopN.sis` → `loopN_dv.sis` (never
edit the original), apply the mechanical rewrite, emit C, compile. On a bug,
**examine the IF1 first** — if IF1 is correct the defect is in C lowering,
otherwise it is in the front end (`to_if1`).

Mechanical rewrite:
- `array[T]` → `array_dv[T]`
- nested `array[OneD]` / `array[TwoD]` → `array_dv[double]` (never nested dv)
- `returns array of` → `returns array_dv of`
- `returns value of` left as-is (FINALVALUE / reduction)

All 24 `_dv` copies generated (loop1_dv pre-existed; made fully dv).

## Fixes landed today

1. **FINALVALUE forall C-lowering (the big unlock).** Every loop is `LoopN`
   kernel + `Main` doing `for i in 1,rep … returns value of X`. That `value of X`
   on an array body was mis-lowered as a **gather + box-then-flatten** →
   `Main(rep=3)` returned rank-2 `REP×n` instead of the last `X`. IF1 was CORRECT
   (a `FINALVALUE` node, output type matched the declared return); the miss was in
   the backend. Fix in `apple_lower.ml`:
   - added `forall_finalvalue_ports` classifier;
   - a **keep-last** arm (assign body value each iteration; no alloc / gather
     counter / box-flatten) — works for array (`loop1` Main → `[581,1261]`) and
     scalar (`loop3` Main → `32`);
   - a **loud assert**: a RETURNS port that is neither REDUCE, FINALVALUE nor
     DV_GATHER now `failwith`s instead of silently gathering;
   - `infer_types` no longer force-seeds `sisal_array_t` for FINALVALUE ports.

2. **Precursor refactor (string → variant).** Replaced the stringly-typed
   `Some "sum"`/`"argmax"` reduce operator with `type reduce_op = R_sum | … |
   R_argmin` + `reduce_op_of_string` (fails loudly on unknown); emission match now
   exhaustive. Deleted the dead `_lower_forall_recursive_OLD` + `zip_loops`
   (878 lines). (Deeper fix — carry a typed operator through IF1 instead of the
   AST-variant→string→variant round-trip in `to_if1` — left on the backlog.)

3. **Plain-array tests removed from e2e.** The new strict `DV_GATHER`-only assert
   surfaced that plain `array of` lowers to `ARRAY_GATHER` (fragile flat-array
   path). e2e is `array_dv` only, so `gen_extent`, `test_mix_array_dv`,
   `test_multi_array_if` were moved back to `test/unit/` and dropped from
   `run_dv_e2e.sh`. Suite 64 → 61 groups.

4. **Missing scalar intrinsics added** (`runtime/sisal_runtime.h`):
   `SABS__I__I`/`__L__L`, `SMAX`/`SMIN` (`II`/`FF`/`DD`),
   `SEXP__FI__F`/`__DI__D` (two-arg **power**), and `SETOTHE__F__F`/`__D__D`
   (= `expf`/`exp`). Unblocked `loop16p`, `builtin_scalar`, `loop22`.
   Semantics clarified: Sisal `exp(b,n)` (2-arg) = power (`pow`); `exp(x)` (1-arg)
   and `etothe(x)` both = e^x (`to_if1` routes 1-arg EXP → ETOTHE → `func__SETOTHE`).
   `etothe` was already an intrinsic on the compiler side; only the runtime body
   was missing.

5. **loop13 paren typo** (fixed in `loop13_dv` only): upstream source wrote
   `MOD2N(integer(Trunc(..),64))`, passing `64` to `integer()` instead of as
   `MOD2N`'s 2nd arg → "no matching function for func_MOD2N". Fixed to
   `MOD2N(integer(Trunc(..)), 64)` on all 4 calls. Original `loop13.sis` untouched.

## Diagnosed, not yet fixed

- **loop2 / loop2s — `to_if1` for-initial MERGE mis-wiring (IF1 IS WRONG).**
  Nested `for initial` with mixed int + array carries (`k`,`i` int; `Xt` array).
  IF1 inspection: the INIT compound's output ports are **permuted relative to the
  MERGE seeds** — `INIT:2/:3` emit the array `OLD X` but feed the integer
  `MERGE_I`/`MERGE_K`; `INIT:4` emits the int `IPNTP` but feeds the array
  `MERGE_XT`. The connecting edges are tagged with the *destination's* type, which
  hid it. `to_if1` matches INIT outputs to MERGE seeds by POSITION; all-int carries
  (the `for_initial_e2e` tests) hide the permutation, mixed int/array makes it a
  hard C type error (`assigning to int32_t from sisal_array_t`). Distinct from the
  FINALVALUE bug (where IF1 was right, backend wrong).
